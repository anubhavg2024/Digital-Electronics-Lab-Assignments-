# Verification – FSM Controller

## Objective

To examine the expected behaviour of the two-bit FSM controller using the request inputs, stored state and output signals.

## State Representation

| State Bit | Description |
|---|---|
| Q1 | Most significant state bit |
| Q0 | Least significant state bit |

The two state bits provide four possible binary state combinations.

| State Combination | Binary Representation |
|---|---|
| State 0 | 00 |
| State 1 | 01 |
| State 2 | 10 |
| State 3 | 11 |

## Input Verification

The circuit has two external inputs, R1 and R0.

| Test | R1 | R0 | Expected Input Combination |
|---|---:|---:|---|
| 1 | 0 | 0 | Neither request is active. |
| 2 | 0 | 1 | Only R0 is active. |
| 3 | 1 | 0 | Only R1 is active. |
| 4 | 1 | 1 | Both requests are active. |

## Sequential Circuit Verification

| Test | Initial State | Clock Condition | Expected Behaviour |
|---|---|---|---|
| 1 | 00 | No active clock edge | State remains unchanged. |
| 2 | 01 | No active clock edge | State remains unchanged. |
| 3 | 10 | No active clock edge | State remains unchanged. |
| 4 | 11 | No active clock edge | State remains unchanged. |
| 5 | Any valid state | Active clock edge | State updates according to the next-state logic. |

## Output Verification

The circuit provides three outputs.

| Output | Expected Function |
|---|---|
| NOGO | Indicates the controller's no-go condition. |
| UP | Indicates the upward-operation condition. |
| DOWN | Indicates the downward-operation condition. |

## Verification Summary

| Verification Parameter | Expected Behaviour |
|---|---|
| Input R1 | Accepted as an external request input. |
| Input R0 | Accepted as an external request input. |
| State storage | Two D flip-flops store the FSM state. |
| Clock operation | State changes occur at the active clock edge. |
| NOGO output | Generated by the output combinational logic. |
| UP output | Generated by the output combinational logic. |
| DOWN output | Generated by the output combinational logic. |

## Verification Notes

The input combinations and state-storage behaviour are identified from the circuit structure.

The exact output combinations and state transitions depend on the Boolean equations implemented by the gates. They must be checked against the final circuit logic.

The verification cases above describe expected structural behaviour rather than recorded simulation results.
